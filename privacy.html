Privacy Policy — step-simulator-progress

This is the isolated synchronization test build of Step Exam Simulator. It is intentionally separate from the production exam-simulator2 deployment.

Effective date: August 8, 2026

What the application stores locally

The simulator stores imported form files, simulator progress, highlights, answer selections, marks, notes, timing information, results, Qbank progress, and related simulator state in browser-local storage or in a user-selected local DATA folder. Local simulator storage remains the primary runtime data source.

Optional Google Progress Backup

If you choose to connect a Google Account, the application requests only the Google Drive application-data permission https://www.googleapis.com/auth/drive.appdata. This permission is used only to create, read, update, and recover the application's hidden progress backup files and small backup manifest in Google Drive's appDataFolder.

The test build uses a small hidden manifest named step-simulator-progress.TEST.manifest.json, one hidden backup file per form/version, and a hidden Qbank backup when Qbank progress exists. These files are stored in Google Drive appDataFolder and are not placed in the user's visible My Drive.

Data sent to Google Drive

Google Progress Backup is designed to back up durable simulator progress such as answers, marks, strikethroughs, highlights, notes, timing/progress state, attempts, results, suspended progress, Qbank history, and selected result metadata. Imported source form files and simulator image/assets folders are not uploaded by the Progress Sync feature.

How Google data is used

Google Drive application data is used only to back up and recover the user's simulator progress across their own browser installations. The application does not use Google Drive data for advertising, profiling, sale, or unrelated analytics.

Servers and sharing

This GitHub Pages application has no application backend or proprietary cloud database for progress synchronization. Progress backup/restore occurs directly between the user's browser and Google Drive APIs. The application does not sell Google user data or share it with advertisers.

OAuth tokens

Google OAuth access tokens are short-lived and are kept only in browser session state. They are not written to simulator IndexedDB progress, Google Drive synchronization snapshots, exported simulator files, service-worker caches, or source code. No OAuth client secret is used in the browser application.

Disconnecting and deleting data

Disconnecting Google Progress Backup on one browser clears that browser's current authorization session and disables automatic backup there. It does not delete local simulator progress and does not revoke access for other devices. It also does not automatically delete the hidden Drive backup files.

Users may delete browser-local simulator data using browser/site-data controls or the simulator's own local progress controls. Google account permissions may be managed from the user's Google Account permissions page. Google Drive app data may also be removed by removing the application's stored data/access through Google account/Drive controls where available.

Test-build safeguards

This test deployment uses separate IndexedDB database names, local-storage keys, service-worker caches, synchronization metadata, and a separate Google Drive TEST-4 manifest and per-form backup namespace so that experimentation does not intentionally modify the production simulator's browser storage or future production synchronization file.

Changes

This policy may be updated if the synchronization implementation or data handling changes. The current version will be published at this page.

Contact

For questions about this application or its data handling, use the developer contact information shown on the application's Google OAuth consent screen or the repository owner's published contact channel.
